# 흐름 설계서 (MCP 여러 개 엮기)

> 원본은 고치지 말고 `결과/흐름_설계서_내꺼.md`로 복사해서 채워요.
> 비유: **릴레이 경주.** 주자(MCP)마다 바통(데이터)을 받아서 다음 주자에게 넘겨요. 바통을 떨어뜨리면 어디서 떨어졌는지 알아야 해요.

**흐름 이름:**                  **만든 날:**
**한 줄 목표:** (예: 매주 월요일, 공방 관련 인기 영상을 기획 DB에 정리하고 카톡으로 알림 받기)

## 1. 전체 그림
```
[입력] ──────────▶ [처리] ──────────▶ [출력]
 YouTube (23)        Notion (10)          카카오톡 나에게 (15)
 영상 찾기           기획 DB에 줄 추가     "3개 정리했어요" 알림
```

## 2. 단계별 설계
| 단계 | 주자 (MCP·도구) | 받는 것 | 하는 일 | 넘기는 것 (모양까지) | 읽기/쓰기 |
|---|---|---|---|---|---|
| ① 입력 | YouTube | 검색어 ❓ | 최근 7일 조회수 상위 3개 찾기 | 제목·채널·조회수·주소 3줄 | 읽기 |
| ② 처리 | Notion | ①의 3줄 | 연습용 "영상 기획" DB에 3줄 추가 | 새 페이지 주소 3개 | **쓰기** |
| ③ 출력 | 카카오톡 | ②의 결과 | 나에게 요약 보내기 | 보낸 메시지 1개 | 보내기(나에게만) |

## 3. 단계마다 확인할 것 (바통 검사)
| 단계 | 확인 방법 | 통과 기준 |
|---|---|---|
| ① | 결과 표를 화면에 먼저 보여 달라고 하기 | 3줄, 조회수가 숫자, 주소가 열림 |
| ② | 노션에서 **직접** 열어 보기 | 3줄이 **연습용 DB**에만 들어감, 중복 없음 |
| ③ | 휴대폰 카톡 확인 | 500자 이내, 노션 주소 포함 |

## 4. 실패하면? (바통을 떨어뜨렸을 때)
| 무엇이 실패 | 증상 | 대처 |
|---|---|---|
| ① 영상이 0개 | 빈 표 | 검색 기간을 14일로 늘려 한 번만 다시. 그래도 없으면 ③으로 "결과 없음"만 알림 |
| ② 노션 연결 끊김 | 권한 오류 | **멈추고** ①의 결과를 `결과/백업_날짜.md`에 저장 후 알림 |
| ③ 카톡 실패 | 보내기 오류 | 결과를 파일로 저장하고 대화창에 보여 주기 |
| ❓ | | |

## 5. 안전 규칙
- 쓰기는 **연습용 노션 DB 한 곳**에만. 그 외 페이지는 건드리지 않아요.
- 보내기는 **카톡 '나에게'**만.
- 같은 영상이 이미 DB에 있으면 **추가하지 않아요** (중복 검사: 영상 주소로 비교).
