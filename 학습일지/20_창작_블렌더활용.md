## 💡 새 개념

- **렌즈 시프트**: 카메라 방향은 그대로 두고 필름만 옆으로 미는 것. 물건 모양은 그대로, 화면 속 위치만 옮긴다 → 글자 빈자리 만들 때 편하다
- **겹쳐 보이게 찍기**: 물건이 옆으로 늘어서 있으면, 그 줄 방향에서 비스듬히 찍어야 좁은 화면에 모인다 (가까이 가면 오히려 벌어짐)
- **카메라 여러 대**: 가로용·세로용·턴테이블용 카메라를 따로 세워 두면 장면 하나로 여러 크기를 다시 찍을 수 있다
- **키프레임**: 처음과 끝만 정하면 블렌더가 사이를 채운다. 반복 영상은 **일정한 속도**로 하고 마지막 장(=첫 장과 같은 그림)은 빼야 끊김이 없다
- **턴테이블 = 회전 진열대**: 회전축에 카메라를 매달고 축만 돌린다. 상세페이지 "360도 제품 영상"이 이 방식
- **ffmpeg = 영상 편집실**: `-framerate 24` 1초에 24장, `-i %04d.png` 0001부터 순서대로, `-c:v libx264` 흔한 압축 방식, `-pix_fmt yuv420p` 어디서나 재생되는 색 형식
- **영상 압축 = 바뀐 점만 적는 일기**: 첫 장만 통째로, 나머지는 달라진 부분만 저장해서 120장이 185KB
- **글자는 HTML로**: 오타·줄바꿈을 1초에 고치고, 문구만 바꿔 새 썸네일·쇼츠를 뽑는다 (렌더는 다시 안 함)
- **조명만 바꾸면 다른 사진**: 낮/저녁은 카메라·물건 그대로, 빛 색·방향만 바꾼다. 어느 쪽이 나은지는 **내용(아침/저녁)과 맞는지**가 먼저, 실제 클릭은 유튜브 A/B 테스트로 숫자 확인

## 📝 포트폴리오 한 줄

- **문제:** 썸네일·쇼츠·제품 회전 영상을 각각 따로 만들면 시간이 많이 들고 모양도 제각각이었다
- **해결:** 블렌더 MCP로 3D 장면 하나에 가로·세로·턴테이블 카메라를 세워 렌더하고, ffmpeg로 120장을 mp4로 이은 뒤, 글자는 HTML로 올려 Chrome DevTools MCP로 쇼츠 화면을 녹화했다
- **효과:** 장면 하나로 썸네일 2종(낮·저녁)·쇼츠 배경·5초 회전 영상·자막 쇼츠까지 뽑았고, 렌더는 한 장 1초 안팎, 문구 수정은 HTML 한 줄로 끝나는 재사용 흐름을 만들었다

## 💬 느낀 점 (Claude가 대신 작성, 내가 확인)

- 장면은 한 번만 지었는데 카메라만 바꿔 가로 썸네일, 세로 쇼츠, 360도 영상까지 나와서 "3D는 한 번 짓고 계속 찍는 것"이라는 말이 실감 났다.
- 키프레임이 생각보다 쉬웠다. 처음과 끝 두 장만 정하면 나머지 119장을 블렌더가 채워 준다. ffmpeg 명령도 부분별로 뜻을 알고 직접 쳐 보니 어렵지 않았다.
- 제목 줄바꿈이 어색했을 때 HTML 한 줄로 바로 고치는 걸 보고, 글자를 렌더에 넣지 않는 이유를 알았다. 상세페이지 회전 영상이나 시리즈 썸네일에 바로 써먹을 수 있을 것 같다.
- MCP 키트 마지막 강의. 노션·통계·DevTools·피그마·블렌더를 거치며 "MCP는 Claude에게 프로그램 손잡이를 쥐여 주는 콘센트"라는 걸 여러 번 느꼈다.
