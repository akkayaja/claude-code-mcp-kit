## 💡 새 개념

- **Context7 = 프로그래밍 공식 설명서 전문 도서관의 사서**: Tailwind·React·pandas 같은 도구의 공식 설명서만, 최신판으로. 웹 검색(아무 페이지나)과 다르고, 내 파일도 안 본다. 공개 문서만 있다
- **사서 + 작가 팀플레이**: Context7은 필요한 쪽을 찾아다 주고, 코드를 쓰거나 고치는 건 Claude
- **결과가 같아도 "근거"가 다르다**: Tailwind 4는 Claude가 이미 알아서 결과는 같았지만, Context7을 쓰면 어느 문서를 보고 썼는지 말할 수 있다
- **진짜 빛나는 때**: Claude가 공부를 마친 **뒤에** 나온 새 버전, 그리고 버전 때문에 난 오류를 고칠 때
- **규칙은 "항상"보다 "필요할 때 꼭"**: 매번 확인하면 느리고 무료 한도에 걸릴 수 있다. 외부 라이브러리 코드와 버전 오류일 때만, 기본 도구는 건너뛰기
- **규칙과 콘센트는 같은 범위에**: 규칙만 모든 폴더에 적고 Context7은 한 폴더에만 꽂으면 다른 폴더에서 지킬 수 없다 → 둘 다 user(집 전체)로

## 📝 포트폴리오 한 줄

- **문제:** AI가 라이브러리 버전이 바뀐 줄 모르고 옛날 방식 코드를 쓸 수 있고, 맞게 썼는지도 근거가 없다
- **해결:** Context7 MCP로 같은 과제를 없이/있이 만들어 비교하고 공식 문서로 검증한 뒤, "외부 라이브러리 코드는 최신 공식 문서를 먼저 확인" 규칙을 내 컴퓨터 전체에 적용했다
- **효과:** 두 결과 모두 공식 v4.3 방식과 일치함을 확인했고, 앞으로 모든 폴더의 코드 작업에서 참고 문서가 자동으로 함께 남는다

## 💬 느낀 점 (Claude가 대신 작성, 내가 확인)

- Context7이 웹 검색이 아니라 코딩 도구의 공식 설명서만 찾아 주는 도서관이라는 걸 알게 됐다.
- 이번엔 Claude가 이미 알아서 결과가 같았지만, 근거가 남는다는 점이 좋았다.
- 매번 명령하지 않아도 되게 모든 폴더 규칙으로 걸어 두니, 앞으로 코드 부탁할 때 더 안심이 된다.
